# 青梧的 Logseq 兼容性说明

> 这份说明告诉你在青梧里打开 Logseq 库，哪些能用、哪些不能用、以及为什么。
> 英文版：[LOGSEQ_COMPATIBILITY_EN.md](LOGSEQ_COMPATIBILITY_EN.md)

## 一句话

青梧把 Logseq 的**文件**读好：打开一个库就能正常阅读、跳转、写长文。它不重实现 Logseq 的**引擎**：query、动态 block 这类需要执行的东西不做——做了就等于把 Logseq 重写一遍，那不是青梧的目标。

## 支持的（阅读与写作）

- **直接打开 vault**。`journals/`、`pages/` 出现在侧栏；`logseq/`（配置、备份）、`assets/` 自动隐藏，不会出现在笔记列表里。
- **任务标记**：`TODO` / `DOING` / `DONE` / `NOW` / `LATER` / `WAITING` / `CANCELED` 在预览里显示为彩色状态徽章。
- **属性行**：`key:: value` 低调呈现；`id::`、`collapsed::` 在阅读时不显示（和 Logseq 的阅读模式一致）。
- **大纲**：Logseq 用 tab 缩进的嵌套大纲，在预览里渲染成正常的多级列表。
- **wikilink**：`[[页面]]` 可点击跳转；支持 `[[target|label]]` 别名、大小写不敏感匹配，以及 `[[namespace/页面]]` 到 `namespace___页面.md` 的文件名映射。
- **块引用**：`((uuid))` 在预览、导出、复制 HTML 时内联展开为被引用块的首行文本（macOS 全库解析；iOS 目前只解析当前笔记内的引用，跨笔记保持原文，V2 补齐）。
- **今日笔记**：`cmd+shift+D` 打开或创建 `journals/yyyy_MM_dd.md`，与 Logseq 的 journal 命名完全一致。
- **安全编辑**：在青梧里编辑并保存笔记时，文件内容按字节保留——`id::` 等属性、行尾、未改动的部分都不会被重写。

## 不支持的（刻意不做）

- **`{{query}}` 动态查询**：需要查询引擎。这是 Logseq 的核心能力，也是它的复杂度来源，青梧不做。
- **动态 block 的完整语义**：块引用目前展开为首行纯文本，不递归展开、不渲染嵌套格式、不随源块实时联动。
- **embed 的编辑联动**：`{{embed}}` 的可编辑嵌入不做。
- **namespace 层级导航**：页面平铺显示，不做树形层级。
- **大纲折叠、块级拖拽**：这是 Logseq 的编辑器交互层，属于"重写 Logseq"的范畴。
- **`.edn` 配置、插件、主题**：不读取、不生效。
- **全文自动排版**：在 Logseq 库里，编辑菜单的 Format 和 Clean Typography 会置灰。这两个功能会重写整个文件，而库拥有自己的格式主权（tab 缩进、`id::` 属性），青梧不与 Logseq 争夺它。在普通 Markdown 文件夹里它们照常可用。

如果你需要以上能力，正确的工具是 Logseq 本体。青梧服务的是"记完之后"的场景：读回库里的内容，把它写成文章。

## 写入约定（信任承诺）

让一个第三方工具打开自己记了几年的库，最怕它偷偷改东西。青梧的规矩：

- **绝不写入 vault 内部文件**，你主动编辑的笔记除外。
- **新建笔记的文件名**遵循青梧自己的约定（macOS 文件名不能含 `/`，层级用 `:` 表示）；Logseq 的 `___` 命名只做只读兼容，不会被改写。
- **置顶和光标位置**以文件扩展属性（xattr）保存，不改变文件字节，`git status` 看不到。
- **冲突备份**存放在 `~/Library/Application Support/com.qingwu.app/Conflicts`，永远不会出现在你的库里。
- **没有遥测和埋点**，所有数据留在本地。
- **同时开 Logseq 和青梧编辑同一篇笔记时请注意**：外部修改按"最后写入生效"处理（编辑器内的未保存内容会自动备份到冲突目录并提示），建议同一篇笔记只在一处编辑。
